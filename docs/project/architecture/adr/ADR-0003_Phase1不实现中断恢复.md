# ADR-0003：Phase 1 不实现中断恢复

**状态：已接受｜范围：P0/P1｜决定：维护者取消中断恢复能力**

## 职责

记录取消中断恢复的架构决定及其取舍，供阶段计划和详细设计引用。

## 非职责

不定义 CLI 参数、状态迁移、删除算法或测试矩阵；这些分别由用户手册、Phase 1 详细设计和研发文档管理。

## 决定

P0-04 故障恢复实验取消，不作为 P0 放行前置。Phase 1 不实现 `doctor --repair`、持久 Operation 重放、创建续做或删除续做。工作区创建只有完整物化并持久化最终证据后才可成为 Ready；清理只有确认整个受控目录已不存在后才报告成功。中断后的残留不自动处理，用户可重新显式授权 `workspace remove --force` 清理归属可证的整个工作区，包括复制进来的 `.git` 目录。

## 背景与备选

原设计为文件系统与 SQLite 跨系统中断建立 operation、意图和 repair 协调。备选是继续实现这套恢复状态机，或在失败时自动删除残留。前者扩大首版状态与测试面；后者可能在无法证明归属时误删。维护者选择先交付基本目录能力，并把残留处理交给新的显式授权。

## 影响与取舍

少一套跨 SQLite/文件系统的恢复状态机，P1 可以先交付普通目录镜像、路径查询和整目录清理。代价是中断后可能留下占空间的非 Ready 目录，须用户显式处置；归属或卷身份无法证明时停止，不以 force 猜测删除。初始化中断留下的非空 data root 不自动接管，由用户在平台外核对和处理。

此决定不取消进程内失败回滚、路径/卷/占用保护、普通清理的已跟踪变更提示或强制清理日志，也不影响 Phase 2 的 WorkspaceCheckpoint 能力。已有未合并 P0-04 实验代码不因此取得产品资格。

## 迁移与验证

同步移除 P0-04 阶段依赖、P1 repair 用例和可重放 Operation 模型；已合并的 P0 物化/Git 实验保持原状。P1 验证创建中断不成为 Ready、删除中断不报告成功、显式强制仅删除已登记的整个工作区目录且日志留在 data root；不以 P0-04 未合并实验作为通过证据。P0/P1 阶段仍须按既有门禁和人工放行。
