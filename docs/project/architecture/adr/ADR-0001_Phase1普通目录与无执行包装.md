# ADR-0001：Phase 1 交付普通目录，不包装用户命令

**状态：Accepted｜依据：维护者明确要求移除命令执行包装｜适用阶段：Phase 1**

> 后续决策说明：无执行包装的结论继续有效；本文“本次不改变 Git/Base 来源”的文字描述的是当时范围，已由 [ADR-0002](ADR-0002_Phase1原始目录镜像与流程交付.md) 的原始目录镜像决策替代，不再限制当前创建输入。

## 职责与非职责

本文记录本次职责收缩的背景、取舍、影响和验证计划。不复制现行命令表、Port 字段、目录布局、任务状态或审核记录；这些事实仍由对应权威文档维护。

## 背景

原方案通过 `workspace exec` 管理用户命令，并为 Rust 项目重定向编译输出。这把语言相关的工具链配置和用户进程生命周期引入了工作区管理层，也使直接使用普通路径变成了次要流程。

## 决策

Phase 1 以普通绝对路径交付工作区，用户、编辑器和 Agent 直接使用原有工具。移除用户命令执行包装及其执行登记、持久化模型和平台构建目录约定，不保留可选包装入口。产品范围以[架构方案](../ThinWorkspace_产品与架构演进方案_v2.1.md)为准。

内部 Git 子进程的可靠性要求仍然保留。删除前的外部占用探测是已有安全责任，收窄为只读能力，不承担启动、终止或托管用户进程。具体职责见[Phase 1 详细设计](../../design/ThinWorkspace_Phase1单机CLI详细设计_v1.0.md)。

## 备选方案与代价

- 保留可选执行包装：仍需维护执行模型和两套使用路径，不采用。
- 按语言增加构建目录或缓存适配：扩大为工具链管理，不采用。
- 底层透明重定向：需要额外文件访问机制及兼容验证，不属于本次调整。

代价是平台不再提供用户命令的超时、信号转发或运行清单；这些由终端、Agent 和构建工具负责。删除前仍只能尽力探测外部进程，不能承诺绝对无占用。

## 迁移与范围

本次为 Phase 1 首次实现、发布前的文档基线修订，不执行数据库迁移，不改实验代码。取消原执行任务并修正依赖，其他任务编号和剩余错误码不重排；任务处置见[实施计划](../../../development/planning/ThinWorkspace_Phase1实施计划_v1.0.md)。

本次不改变 Git 导入来源或 Base 内容边界，也不新增编译缓存导入、缓存命中保证或共享策略。已有缓存目录的 CoW 克隆若另行纳入产品，需先定义来源一致性与验收条件，不能由本决策推导为已支持。

## 验证计划

- 检查架构、详细设计、用户手册、技术栈和计划，不残留执行包装的正向契约或依赖。
- 检查路径、状态、JSON、错误码、删除和 GC 示例的一致性，以及内部 Git 可靠性和外部占用保护未被误删。
- Phase 1 实现时，以直接进入工作区运行已有工具作为端到端验收；未知执行子命令按通用参数错误处理。
- 本次仅验证文档与仓库基础门禁，不将其当成 Phase 1 功能或阶段放行证据。
