## 可执行验收断言

| 子步 | 必须证明的结果 |
|---|---|
| 纯状态解析与决策 | 正确处理 porcelain v2 的普通、重命名/复制、冲突及 NUL 路径；按报告路径去重，未跟踪/ignored 不计入；截断或未知记录不冒充 clean。unknown 优先于 dirty；完整无仓库为 not-applicable。force 只解除内容检查，不能解除路径/卷或 confirmed-in-use |
| 真实只读 Git | 自包含根仓库、嵌套仓库、内部 submodule：暂存/未暂存/新增/删除/重命名/冲突/gitlink 修改准确；父子仅 untracked 时均不 dirty；无仓库不向父目录发现。检查前后 refs/index/config 与测试树外 sentinel 不变 |
| 安全与不完整 | 外部 gitfile/commondir/worktree、失效引用、扫描错误、隐藏 index flags/sparse、filter 和 promisor 返回真实 unknown；父仓库递归查询前完成子仓库预检。环境污染和恶意配置不能触发未批准程序、联网或对来源的写入 |
| 有界内部调用 | 固定 Git argv、显式 cwd 与净化配置/环境；退出码、stderr、超时、输出限额及退出后管道未关闭分别有回归，不建立用户命令执行入口 |
| 清理与持久日志 | 普通 dirty/unknown 拒绝且文件不变；force 绕过内容检查但不越界。真实日志先持久开始事件再删除自有测试副本，之后仍可读取结果；即使 clean、JSON 或低日志级别也不漏记 force。日志失败不先删除，中断仅有 started 不伪造 completed，控制字符转义，无源码/未跟踪清单泄漏 |

重命名使用 Git 报告的目标路径作为一项变更，原路径只参与记录完整性检查；不把一次重命名计为两条。验证对象是当前 HEAD/index，不扫描全部历史；本机 commit 不等于已推送或交付，实验不增加此类准入检查。

3. 最后在全新受控临时根下验证日志与获准清理；启动前记录实际根、对象身份、删除范围和保留策略。不运行任意路径删除，不操作真实用户源码或旧任务现场。这里只验证最小开始/结果边界，跨系统 operation 恢复仍由 P0-04 承接。
4. 冻结代码，执行适用变异、fuzz、真实 release 验证及规定模型审核，跟进精确候选 PR/CI。所有验收断言齐备前不标 Done，不宣称 P0.b 或 P0 放行。

各子步保持单一写入负责人。主 Agent 维护文档、fuzz/CI 集成和 PR；编码 Agent 只写派发范围。未知身份失败现场保留，不用默认 TempDir 析构或递归删除绕过停止结论；实测清理前由主 Agent 核验范围。
