# ADR-0002：Phase 1 原始目录镜像与流程交付

**状态：Accepted｜依据：维护者于 2026-09-13 确认首版简化方案｜适用阶段：Phase 0 / Phase 1**

## 职责与非职责

本文记录本次方向调整的原因、取舍和验证要求。不复制命令、字段、状态机、日志格式或任务状态；这些分别由用户手册、详细设计、开发规范和实施计划维护。

## 背景

旧方案从 Git 提交生成 Base，再建立托管 bare repository 和 linked worktree。它不能直接保留来源目录中现有的未提交文件和构建产物，并把 checkout、属性转换、分支拓扑和提交回收引入了目录物化层。

维护者确认首版只需要原始目录镜像、普通路径使用和简单清理；任务必须提供 commit 的要求由 LLM 与主管 Agent 的研发流程执行，不由底层删除命令强制执行。

## 决策

- 创建以本机现有目录为输入，不要求接入 Git，不从提交重建文件，不管理 Repository、Git Base 或平台分支。
- 创建与物化不按 Git 跟踪或忽略规则筛选文件；普通命令直接使用副本路径。
- 清理前按需只读检查主仓库和子仓库的已跟踪变更。未跟踪文件不提示、不阻塞；显式强制清理可以绕过内容检查。
- 强制清理及检查异常写入工作区之外的普通持久日志。不增加独立审计系统、提交证明库或 LLM 调用。
- commit、push、PR、成果持久保存和主管验收由外部任务流程管理，不作为底层不可绕过的释放条件。路径归属、卷身份和删除范围保护不撤销。

产品范围见[架构方案](../ThinWorkspace_产品与架构演进方案_v2.1.md)；内部职责见[详细设计](../../design/ThinWorkspace_Phase1单机CLI详细设计_v1.0.md)；公开交互见[用户手册](../../reference/ThinWorkspace_Phase1用户操作手册_v1.0.md)；交付要求见[任务流程](../../../development/process/任务流程.md)。

## 备选方案与代价

不采用“释放自动提交、推送并创建 PR”，也不采用“验证所有提交已发布后才允许释放”：两者把团队交付政策和网络权限变成目录清理的前置依赖。

纯目录镜像不自动修复外部引用：复制的 Git 指针或符号链接可能仍指向来源之外。逐文件 CoW 也不是活跃目录的应用一致性快照。首版明确这些限制，不扩建 Git 重定位、透明重定向或解锁机制。

删除副本会删除其中的 Git 元数据；本机 commit 不自动等于已保存到副本之外。未跟踪文件也可能被普通清理直接丢弃。上述取舍由维护者确认，外部任务流程负责成果保存，产品不能把“清理成功”描述为“交付成功”。

技术事实参考：[Git 仓库布局](https://git-scm.com/docs/gitrepository-layout)、[Git status](https://git-scm.com/docs/git-status)、[Apple clonefile](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/clonefile.2)。接口事实不等于新流程已实测。

## 迁移与验证

这是首次产品发布前的设计修订，不执行代码或数据库迁移。旧 Git/Base 实验及失败证据保留为历史，不将未完成任务标成通过；取消及替代依赖只由[实施计划](../../../development/planning/ThinWorkspace_Phase1实施计划_v1.0.md)维护。ADR-0001 的无执行包装决策继续有效，其当时的 Git/Base 来源边界由本决策替代。

先验证非 Git 目录和完整目录内容物化，再验证已跟踪变更检查、嵌套仓库、强制清理日志及故障恢复。新行为需要真实 APFS/Git 验收；本次文档修订不代表实现完成或阶段放行。
