## 已核对的复用点（不是实测结果）

- 本机锁定的 `rustix 1.1.4` 提供 `fs::flock` 和 `fs::fcntl_lock` 安全 API，macOS 未被其条件编译排除。其 libc 实现把非阻塞独占的 `fcntl_lock` 映射为 `F_SETLK/F_WRLCK`，范围从偏移 0 到文件末尾（`l_len=0`），符合首轮重叠范围验证。可先复用已有依赖，不能因需要两种锁而另引 `nix` 或复制一套 FFI。
- 已有 `thinws-p0-materialize::materialize_once` 接收 `MaterializeRequest` 和显式 `Backend::ApfsFileClone/FullCopy`，返回实际调用及文件身份等证据。准备采用该入口验证独立副本，不用 `cp -c` 或复制成功的布尔值替代 CoW Receipt。
- 已有 materialize 测试的 `ControlledTree` 没有 Drop 清理，并保存 no-follow 身份记录；后续按其现有能力评估复用，不为本实验改写其他任务的清理边界，也不把历史验证自动计入新实验。

## 已冻结的执行约束

1. 持锁者与竞争者必须是独立进程，分别打开目标；子进程只运行当前测试二进制的固定内部入口。固定收到加锁成功的握手后才执行物化或竞争，不用 sleep 猜测锁状态。握手/消息读写上限 5 秒，单子进程总观察上限 30 秒，诊断输出上限 64 KiB；异常只终止自有 Child，另给最多 1 秒确认退出，无法确认则本场景失败并保留现场，不无限 wait。
2. 持锁者在观察期间保持同一个 FD 和锁，不在该进程读取摘要或额外打开/关闭该文件，避免传统 POSIX 锁因关闭同文件其他 FD 而释放。协调进程负责物化、内容/身份记录和对照。
3. 每种锁分别建立同文件/别名冲突阳性对照；对照无效立即停止该场景，不能继续报告副本隔离。任何失败或超时保留原结果，不通过改写断言迁就文献预期。
4. 所有写入、硬链接/符号链接、rename、时间恢复及权限拒绝场景只使用新建实验树和自有进程。替换不迁移旧 FD；原地写入不预设新 inode；不扫描或修改真实用户缓存，不删除 `.lock` 标记，不终止外部进程。
5. 明确普通结束、中断和失败时的处置：优先保留文件与证据；终止只针对本次直接创建且身份可核对的测试子进程，退出结果须有界确认。任何测试数据删除须列出精确对象和身份依据，不使用递归清理命令或隐式析构抹除失败现场。

实现采用独立集成测试目标 `lock_isolation`，复用 `thinws-p0-materialize` 的既有依赖和物化入口；不为仅验证系统 API 增加产品层或空库。冻结命令如下，目标接线之前不报告为已执行：

