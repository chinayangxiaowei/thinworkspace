### 第二子步的首项：限定 Git 调用（准入）

纯解析提交 `08e2b648baab164b1ce203ec666cc1ef6df6cd35` 已保存并推送；规定审核按该精确提交进行。接下来先实现 GitInspector 所需的小型内部调用函数，再连接发现和安全预检，不创建用户命令入口或通用执行器。

本实验冻结的单调用边界：总运行/输出收集预算 5 秒，stdout 上限 8 MiB、stderr 上限 256 KiB；拒绝无限读取和只等 child exit 不等输出关闭。超时、超限或读取错误时只处理本次直接启动的子进程，最多再用 500 毫秒确认退出；未确认必须报告，不用无限 wait 或把 drop 当作回收证据。短轮询间隔 5 毫秒；短预算测试只通过私有注入改变，不增加 CLI 参数。

对外仅允许固定 `/usr/bin/git` 的 version、单文件 config 解析、tracked status、index flags 查询变体及所需路径参数；通用 `Command` 收集函数保持模块私有。返回实际 exit/signal、分别限额的 stdout/stderr 和结构化失败/回收状态，不自行解析状态或决定清理。原始输出只作为内存输入，不进入日志或 Debug 展示。

采用技术栈已批准、仓库已锁定的 `rustix` 安全非阻塞 FD API；不添加第二套 OS FFI，不放宽 `forbid(unsafe_code)`。净化环境、禁止交互和命令级覆盖仍按技术栈执行；此函数不负责证明配置转换或外部元数据安全，调用者完成预检之前不得用它进入真实用户仓库，也不能仅因净化后的命令成功就报告 clean。实际自包含/子仓库发现与外部配置判断仍是本子步的后续必需工作。

RED 断言覆盖成功双通道/非零 exit、stdout 和 stderr 各自超限、运行超时、直接子进程退出但输出仍被继承、启动失败和未确认退出的报告。仅运行固定 Git 版本查询或测试自身的受控子进程；不操作用户工具、不挂载/清理镜像、不触碰旧现场。本项完成仍不代表真实 Git 检查或 P0-07 完成。

实际编码仍使用 GPT-5.6 Sol / `xhigh`。有效 RED：模块编译成功，8 个行为断言因固定返回错误的 stub/未确认映射失败，1 个受控测试 helper 通过，exit 101；随后进入 GREEN。本次新增结果不能沿用首个纯逻辑提交的审核结论。

单文件配置解析可改用固定、已验证为字符设备的 `/dev/null` 作为显式 git-dir，避免引入独立 query-cwd 生命周期。主 Agent 在实际有父仓库的 cwd 对自有 include 夹具做过对照：Config 精确返回两条记录、exit 0；同前缀的发现对照 exit 128、无父仓库输出。该变体仅用于配置解析，不用于 status/index，不构成 Sandbox；[启动源码](https://github.com/apple-oss-distributions/Git/blob/Git-154/src/git/setup.c)已与 GPT-6 Astra / `xhigh` 准备性分析交叉核对。

实施按“no-follow 完整发现 → 所有根/子仓库元数据与配置预检 → 全部相关 IndexFlags → 叶子到父级状态查询 → 证据复核与聚合”推进。必须保留正常内部 submodule 相对 gitfile/core.worktree 的成功路径；不可安全检查的子仓库不能先被父 status 访问。include、filter、promisor、隐藏索引及未核实副作用走既定 unknown，不加自动修改或联网补救。

本次实验资源上限冻结为整体协作式预算 60 秒（每次 Git 调用使用既有上限与剩余预算的较小者，故障清理仍使用既有预算）、最多 100,000 个扫描项、256 个仓库、128 层目录、单份配置/引用文本 1 MiB；达到上限如实报告不完整，不截断后冒充完整。常规文件系统调用不承诺硬实时中断或同 UID 对抗性隔离。先建可失败的真实根仓库、ignored 目录内嵌套仓库、内部 submodule、外部配置/attributes 与父查询前拒绝用例，再做最小实现；所有夹具归属明确并保留，不自动清理旧现场。
