### 第二子步的首项：限定 Git 调用（准入）

纯解析提交 `08e2b648baab164b1ce203ec666cc1ef6df6cd35` 已保存并推送；规定审核按该精确提交进行。接下来先实现 GitInspector 所需的小型内部调用函数，再连接发现和安全预检，不创建用户命令入口或通用执行器。

本实验冻结的单调用边界：总运行/输出收集预算 5 秒，stdout 上限 8 MiB、stderr 上限 256 KiB；拒绝无限读取和只等 child exit 不等输出关闭。超时、超限或读取错误时只处理本次直接启动的子进程，最多再用 500 毫秒确认退出；未确认必须报告，不用无限 wait 或把 drop 当作回收证据。短轮询间隔 5 毫秒；短预算测试只通过私有注入改变，不增加 CLI 参数。

对外仅允许固定 `/usr/bin/git` 的 version、单文件 config 解析、tracked status、index flags 查询变体及所需路径参数；通用 `Command` 收集函数保持模块私有。返回实际 exit/signal、分别限额的 stdout/stderr 和结构化失败/回收状态，不自行解析状态或决定清理。原始输出只作为内存输入，不进入日志或 Debug 展示。

采用技术栈已批准、仓库已锁定的 `rustix` 安全非阻塞 FD API；不添加第二套 OS FFI，不放宽 `forbid(unsafe_code)`。净化环境、禁止交互和命令级覆盖仍按技术栈执行；此函数不负责证明配置转换或外部元数据安全，调用者完成预检之前不得用它进入真实用户仓库，也不能仅因净化后的命令成功就报告 clean。实际自包含/子仓库发现与外部配置判断仍是本子步的后续必需工作。

RED 断言覆盖成功双通道/非零 exit、stdout 和 stderr 各自超限、运行超时、直接子进程退出但输出仍被继承、启动失败和未确认退出的报告。仅运行固定 Git 版本查询或测试自身的受控子进程；不操作用户工具、不挂载/清理镜像、不触碰旧现场。本项完成仍不代表真实 Git 检查或 P0-07 完成。
